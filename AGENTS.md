# AGENTS.md

Guidance for coding agents working in this repo. `README.md` is the user
manual; this file is what you need to change the code without undoing a
decision someone already made on purpose.

## What this is

A browser extension for Firefox and Chrome that reads web pages aloud with
Kokoro TTS. Two engines produce the same response: Kokoro in the browser on
WebGPU (no install; sentence-exact, word-estimated highlighting), and a local
Python server (exact word highlighting, much faster).

```
extension/            MV3 extension, plain JS, one tree for both browsers
  engine/             GENERATED by `npm run build`, gitignored: the bundled
                      browser engine and onnxruntime's wasm
  background.js       injection, TTS relay, player control
                      (Chrome: service worker; Firefox: event page)
  content.js          toolbar, extraction, highlighting, playback state
  offscreen.js/.html  audio player (Chrome: offscreen document;
                      Firefox: loaded into the background page itself)
  popup.*             settings
  lib/textkit.js      pure text logic: extraction, sentences, text index, spans
  lib/record.js       the page's sentence record: synthesis order, kept audio
engine/               source of the browser engine (ES modules)
  engine.mjs          kokoro-js on WebGPU, loaded lazily by the player
  speechkit.mjs       pure logic: sentences → server-shaped response
scripts/build-engine.mjs  bundles engine/ into extension/engine/
scripts/build-packages.mjs  copies extension/ per browser into dist/, zips with --zip
scripts/manifests.mjs     each browser's manifest, derived from the source one
dist/                     GENERATED, gitignored: dist/chrome/, dist/firefox/, the zips
server/               FastAPI + Kokoro, managed with uv
  src/tts_server/alignment.py   token → character spans, kept free of torch
  src/tts_server/device.py      cuda → mps → cpu choice, kept free of torch
tests/                node:test suites for the extension
  fixtures/pages/     saved pages the extractor is tested against
spikes/               timeboxed experiments, not shipped
todo/                 work items (see Workflow)
```

## Commands

```bash
npm install                      # once
npm run build                    # browser engine → extension/engine/, then dist/chrome/ and dist/firefox/
npm run package                  # the same, plus one store zip per browser in dist/
npm test                         # extension suite (no build needed)

uv run --directory server --no-project --with pytest --with httpx --with starlette pytest
                                 # server suite without installing torch

uv sync --directory server       # full server install (CUDA torch ~2.6GB; PyPI torch with MPS on macOS)
uv run --directory server uvicorn tts_server.main:app --port 7860
```

CI (`.github/workflows/test.yml`) runs both suites on Node 22/24 and Python
3.10/3.13. Neither suite needs a GPU or a browser.

## Decisions not to undo

Each of these was a fix. Reverting one brings the bug back.

- **Content scripts are injected on demand**, never declared in the manifest
  for `<all_urls>` (000013). `activeTab` grants access from the action click,
  the context menu and the shortcut. `tests/manifest.test.js` enforces it.
- **No wildcard host permissions** (000007). Only localhost hosts may appear,
  and the test enforces this too.
- **Audio is always synthesized at 1.0x.** Playback speed comes from
  `audio.playbackRate`. Synthesizing at a rate as well would compound the two
  speeds (000002).
- **Service-worker state lives in `chrome.storage.session`,** not in module
  variables, because Chrome evicts the worker after about 30s idle (000005).
- **The offscreen document's existence is queried** with `getContexts`, never
  remembered in a flag.
- **`alignment.py` and `device.py` must not import torch, numpy or soundfile.**
  `device.py` takes torch as an argument (000049). The cheap
  server test run depends on it.
- **Browser speech fallback is opt-in, off by default** (000018).
- **Extraction reads the live page with our own rules** (000058), not
  Readability, which dropped short comments and made highlighting search a
  copy of the page. Extraction and the text index share one skip rule
  (`skipRule` in textkit), so every paragraph is an exact run of the indexed
  text. Change what is skipped only there, so both sides change together. A site
  that reads badly gets a fixture in `tests/fixtures/pages` and a test.
- **One manifest serves both browsers** (000044). The store packages are derived
  from it by `scripts/manifests.mjs` (000055), each with only its own browser's
  keys; edit `extension/manifest.json`, never a copy in `dist/`. `background` carries both
  `service_worker` (Chrome) and `scripts` (Firefox), and each browser ignores
  the other's key. Firefox loads `offscreen.js` ahead of `background.js` in one
  page, where `runtime.sendMessage` never reaches that page's own listeners, so
  the two talk by direct call (`ReadAloudPlayer`). Never route player traffic
  back through runtime messages. `tests/firefox-background.test.js` loads both
  files together to catch it.
- **Something must message the background at least every 30s while a reading
  session is open.** Firefox suspends an event page after about 30s without
  an incoming event, which would cut audio off mid-chunk and drop the loaded
  browser engine. The toolbar's 15s `HEALTH_CHECK` poll does this for the
  whole session, and `KEEPALIVE` does it during playback. Do not stretch the
  poll past 30s.
- **The browser engine runs WebGPU at fp32 on onnxruntime-web 1.31 or later**
  (spike 000025, item 000046). Never use the `kokoro.web.js` bundle: it pins
  onnxruntime-web 1.22.0-dev, which produces static on Firefox's WebGPU.
  `scripts/build-engine.mjs` refuses to build against an older runtime. fp16
  hangs on Firefox, and WASM is 0.5–0.8x realtime, slower than listening.
- **The engine returns exactly the server's response shape**, so `content.js`
  never needs to know which engine spoke. Keep it that way.
- **No code from a CDN.** MV3 forbids it. The engine and onnxruntime's wasm are
  bundled; only model weights and voices are fetched (from Hugging Face), and
  they are data. `'wasm-unsafe-eval'` in the manifest CSP is for that wasm.
- **Firefox 140 is the floor**, because the highlighting needs the CSS Custom
  Highlight API.

## Code conventions

- Plain JS that browsers load directly: no modules in content scripts, no
  dependencies in `extension/`. The one exception is the browser engine,
  bundled from `engine/` because its dependencies (kokoro-js, transformers.js,
  onnxruntime-web) cannot come from a CDN. Keep the bundle boundary there.
- Comments explain *why*, often citing the item that motivated the code.
  Keep that habit, and keep existing comments accurate when behaviour changes.
- Tests load the real source files into a `vm` sandbox with stubbed `chrome`
  APIs, so they break when a file changes. Extend that pattern rather than
  extracting functions for testing.

## Workflow

- Work items live in `todo/` and are managed only through the todo CLI
  (`~/.claude/skills/todo/todo`). Never hand-edit an item or `BOARD.md`.
- Every change starts from an item and goes on a branch named
  `feat|fix|chore/{id}-{slug}`. Nothing is committed to `main`; changes land by
  PR.
- Commit subjects use conventional prefixes (`feat:`, `fix:`, `chore:`,
  `test:`, `spike:`).
